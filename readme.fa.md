# ایران‌نان‌ترنت

[English](readme.md) · **فارسی** · [ویکی](wiki/fa-Home.md)

یک برنامه دسکتاپ برای پایش سرور و سایت، که قطعی واقعی را از فیلتر منطقه‌ای تشخیص می‌دهد.

اگر چیزی را روی شبکه ایران بالا آورده باشید این سناریو را می‌شناسید: سایت از میز کار خودتان بی‌عیب
بالا می‌آید، پس هیچ چیز مشکوک به نظر نمی‌رسد، در حالی که هر بازدیدکننده‌ای بیرون از کشور تایم‌اوت
می‌گیرد. یا برعکس: همه‌جا بالاست جز روی یک اپراتور موبایل. مونیتورهای معمول آپ‌تایم فقط از یک نقطه
می‌پرسند «بالاست یا نه؟» و این دقیقاً همان سؤالی است که نمی‌تواند این حالت‌ها را از هم جدا کند.

ایران‌نان‌ترنت هر سایت را هم‌زمان از شبکه خودتان **و** از نودهای داخل و خارج ایران بررسی می‌کند و
بعد نوع خرابی را نام می‌برد، نه اینکه فقط یک پرچم قرمز نشان دهد. علاوه بر این سرورهای SSH، کانتینرهای
داکر، گواهی‌های TLS و ثبت دامنه را هم زیر نظر می‌گیرد تا چیزهایی که معمولاً بی‌صدا خراب می‌شوند در یک
پنجره جمع باشند.

با Tauri، Rust و React ساخته شده. روی مک، ویندوز و لینوکس اجرا می‌شود.

## چه چیزهایی را پایش می‌کند

### وب‌سایت، همراه با حکم

هر بررسی یک درخواست مستقیم از دستگاه خودتان را با یک probe از نودهای
[check-host.net](https://check-host.net) ترکیب می‌کند. از هر شبکه فقط یک نود انتخاب می‌شود، پس اگر یک
اپراتور خاص مسیر را انداخته باشد به چشم می‌آید و در میانگین گم نمی‌شود. بعد دو نتیجه با هم مقایسه
می‌شوند:

| شبکه شما | خارج ایران | داخل ایران | حکم |
| --- | --- | --- | --- |
| در دسترس | همه ناموفق | — | **ایران‌اکسس** — فقط از داخل کشور در دسترس است |
| ناموفق | بعضی موفق | — | **مسدود روی این شبکه** — مشکل ISP یا DNS شماست، نه سرور |
| — | بعضی موفق | همه ناموفق | **از داخل ایران در دسترس نیست** — ورودی فیلتر شده |
| ناموفق | همه ناموفق | همه ناموفق | **داون** — قطعی واقعی |
| در دسترس | در دسترس | بعضی ناموفق | **قطعی جزئی اپراتور** — هشدار، با نام شبکه‌های ناموفق |

خطای HTTP هم ثابت می‌کند که میزبان جواب داده است، پس یک ۴۰۴ به‌عنوان «در دسترس» حساب می‌شود و هرگز
به‌عنوان قطعی گزارش نمی‌شود. نودهایی که کارشان تمام نشده «نامشخص» در نظر گرفته می‌شوند، نه ناموفق.

چون check-host.net نرخ درخواست را محدود می‌کند، بررسی خارجی زمان‌بندی کندتر خودش را دارد (پیش‌فرض
۱۵ دقیقه) و بررسی محلی بازه کوتاهش را نگه می‌دارد. آخرین نتیجه خارجی بین دو probe حمل می‌شود.

### سرور از طریق SSH

هر بررسی یک اتصال می‌زند، یک دستور تکه‌ای می‌فرستد و خروجی را سمت خودمان پارس می‌کند:

- بار پردازنده نرمال‌شده به ازای هر هسته، از `/proc/loadavg` و `nproc`
- حافظه از `/proc/meminfo`، با اولویت `MemAvailable` و فالبک به free + buffers + cached
- مصرف دیسک برای هر مسیر مانت از `df -Pk`، دقیقاً مطابق روشی که خود `df` ظرفیت را حساب می‌کند
- وضعیت و هلث‌چک کانتینرها از `docker ps`

چیزی روی سرور نصب نمی‌شود و به ایجنت نیازی نیست. حدها برای هر سرور جداگانه تنظیم می‌شوند و مصرف بالای
۹۷٪ از هشدار به بحرانی ارتقا پیدا می‌کند، چون همان‌جاست که بکاپ‌ها شروع به شکست خوردن می‌کنند.

ورود با کلید خصوصی یا رمز عبور کار می‌کند. کلید توصیه می‌شود و رابط کاربری هم همین را می‌گوید.
کلید میزبان در اولین اتصال پین می‌شود: اثر انگشت ثبت می‌شود و تغییر بعدی به‌عنوان بحرانی گزارش می‌شود،
نه اینکه بی‌صدا پذیرفته شود.

نام کانتینر اول به‌صورت دقیق مطابقت داده می‌شود و بعد به‌صورت زیررشته، پس `db` با کانتینر کامپوزی به
نام `stack-db-1` هم می‌خورد.

### گواهی و دامنه

انقضای TLS از گواهی‌ای خوانده می‌شود که در یک هندشیک واقعی ارائه شده، پس آن چیزی را می‌بینید که
بازدیدکننده می‌بیند. شدت هشدار با نزدیک شدن ضرب‌الاجل بالا می‌رود، نه اینکه یک هشدار یکنواخت بدهد.

انقضای ثبت دامنه از RDAP می‌آید، روزی دو بار و نه در هر سایکل، چون این تاریخ سالی یک بار عوض می‌شود و
رجیستری‌ها کوئری تکراری را تراتل می‌کنند.

دامنه‌های `.ir` یک استثنای مستندشده هستند: سرور whois آیرنیک تاریخ انقضا را از جواب‌هایش فیلتر می‌کند
و سرویس RDAP برای `.ir` وجود ندارد، پس این تاریخ به هیچ روشی قابل دریافت نیست. به جای گزارش یک خطای
استعلام که کاری از دستتان برنمی‌آید، این دامنه‌ها «منتشرنشده» علامت می‌خورند و بررسی گواهی مثل همیشه
انجام می‌شود.

دامنه قابل ثبت با یک هیوریستیک کوچک پسوند استخراج می‌شود، نه با فهرست کامل public suffix. این روش برای
حالت‌های رایج از جمله `.co.uk` و `.co.ir` درست است ولی جامع نیست.

## اطلاع‌رسانی

هشدارها به نوتیفیکیشن سیستم‌عامل، وب‌هوک دیسکورد و ربات تلگرام می‌روند، به هر ترکیبی که تنظیم کرده
باشید. دو رفتار باعث می‌شود این هشدارها به‌دردخور بمانند:

- هشدار فقط وقتی می‌آید که حکم واقعاً عوض شود، نه در هر سایکل
- یک خرابی باید چند بار پشت سر هم تکرار شود تا اعلام شود، پس یک پکت گم‌شده بیدارتان نمی‌کند. بازگشت
  به حالت سالم همیشه فوری اعلام می‌شود.

بستن پنجره برنامه را نمی‌بندد؛ در نوار وضعیت می‌ماند تا بررسی‌ها ادامه پیدا کند.

## داده‌ها کجا نگه داشته می‌شوند

موارد پایش و تنظیمات به‌صورت JSON ساده در پوشه تنظیمات پلتفرم ذخیره می‌شوند، با نوشتن اتمیک تا یک
ذخیره نیمه‌کاره نتواند فایل را ناقص کند:

- مک `~/Library/Application Support/net.nanternet.monitor/targets.json`
- لینوکس `~/.config/net.nanternet.monitor/targets.json`
- ویندوز `%APPDATA%\net.nanternet.monitor\targets.json`

رمز SSH، عبارت عبور کلید و توکن ربات تلگرام هرگز به آن فایل نمی‌روند. این‌ها در انبار اعتبارنامه
سیستم‌عامل ذخیره می‌شوند: Keychain روی مک، Credential Manager روی ویندوز و Secret Service روی لینوکس.

## اجرا

به Node نسخه ۲۰ یا بالاتر، یک تول‌چین Rust و
[پیش‌نیازهای سیستمی Tauri](https://v2.tauri.app/start/prerequisites/) برای پلتفرم خودتان نیاز دارید.

```sh
npm install
npm run app          # پنجره توسعه با هات‌ریلود
npm run app:build    # بیلد نهایی برای پلتفرم جاری
```

تست‌های بک‌اند همان بخش‌هایی را پوشش می‌دهند که بی‌صدا خراب می‌شوند، یعنی پارسرها و منطق حکم:

```sh
cd src-tauri && cargo test
```

`tools/make-icon.py` آیکن برنامه را از صفر و بدون هیچ وابستگی گرافیکی می‌سازد؛ خروجی‌اش را به
`npx tauri icon` بدهید.

## ساختار

```
src/                    رابط کاربری React
  components/           Dashboard، ServerList، AddServerModal، Settings
  i18n/                 دیکشنری انگلیسی و فارسی، مدیریت RTL
  useMonitor.ts         پل دستورها و رویدادها به بک‌اند
src-tauri/src/
  network_checker.rs    probe محلی و قوانین حکم
  checkhost.rs          کلاینت check-host.net، انتخاب نود، پارس نتیجه
  ssh_manager.rs        ترنسپورت SSH، پین کلید میزبان، پارس منابع
  docker_monitor.rs     پارس وضعیت و هلث‌چک کانتینر
  cert_watch.rs         بازرسی هندشیک TLS و RDAP
  notification_engine.rs  تحویل به دسکتاپ، دیسکورد و تلگرام
  scheduler.rs          حلقه زمان‌بندی و تشخیص تغییر وضعیت
  secrets.rs            انبار اعتبارنامه سیستم‌عامل
```

## زبان

رابط کاربری با انگلیسی و فارسی عرضه می‌شود و چیدمان راست‌به‌چپ کامل دارد. اضافه کردن یک زبان یعنی یک
فایل دیکشنری کنار `src/i18n/en.ts` و یک سطر در `src/i18n/index.tsx`.

## مستندات

پوشه `wiki/` راهنمای کامل را به هر دو زبان دارد و از [wiki/fa-Home.md](wiki/fa-Home.md) شروع می‌شود.
همه تنظیمات، شکل دقیق فایل کانفیگ و اینکه وقتی یک بررسی چیز غیرمنتظره‌ای گزارش داد چه کار کنید،
آنجا توضیح داده شده.

این فایل‌ها به شکل صفحه‌های ویکی گیت‌هاب چیده شده‌اند، پس منتشر کردنشان به اندازه یک push کار دارد:

```sh
git clone https://github.com/drstreet/nanternet.wiki.git /tmp/nanternet-wiki
cp wiki/*.md /tmp/nanternet-wiki/
cd /tmp/nanternet-wiki && git add . && git commit -m "Sync wiki" && git push
```
